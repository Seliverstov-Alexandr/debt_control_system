Debt Control System
Automated System for Accounts Receivable Control and Analysis
Автоматизированная система контроля и анализа дебиторской задолженности предприятия

Данный репозиторий содержит исходный код программного прототипа, разрабатываемого в рамках выпускной квалификационной работы (ВКР). Система представляет собой десктопное приложение с клиент-серверной архитектурой.

 Архитектура проекта
Система разделена на три логических уровня:

Desktop (Клиент): PyQt6. Пользовательский интерфейс.

Backend (Сервер): FastAPI + SQLAlchemy. Бизнес-логика, REST API, доступ к данным.

Database (Хранилище): PostgreSQL. Реляционная база данных.

 Структура проекта и назначение файлов
Ниже приведено подробное описание структуры каталогов и назначения каждого ключевого файла.

 Корневой каталог
.env.example — Шаблон переменных окружения. Содержит примеры строк подключения к БД и настройки API. Реальный файл .env создается на его основе и не попадает в Git.

.gitignore — Список файлов и папок, которые Git должен игнорировать (виртуальное окружение, кэш Python, файлы .env, сгенерированные отчеты).

docker-compose.yml — Конфигурация для запуска СУБД PostgreSQL в изолированном контейнере Docker.

requirements.txt — Список всех Python-зависимостей проекта (FastAPI, SQLAlchemy, PyQt6 и др.).

README.md — Этот файл. Основная документация проекта.

LICENSE — Файл лицензии.

 backend/ (Серверная часть)
Каталог содержит весь код, относящийся к серверной логике и работе с базой данных.

alembic.ini — Конфигурационный файл для инструмента миграций Alembic.

alembic/ — Каталог скриптов миграций. Здесь хранятся версии изменений структуры БД.

env.py — Настройки окружения Alembic (подключение к БД, импорт моделей).

versions/ — Сгенерированные файлы миграций (создание таблиц, изменение полей).

 backend/app/ (Ядро приложения)
main.py — Точка входа в FastAPI приложение. Здесь создается экземпляр app, подключаются маршруты (роутеры) и настраивается CORS.

__init__.py — Делает директорию Python-пакетом.

 core/ (Системные настройки)
config.py — Класс настроек (на базе Pydantic). Загружает переменные из .env (URL базы данных, хост, порт).

database.py — Инициализация SQLAlchemy: создание engine (движка подключения к PostgreSQL), SessionLocal (фабрики сессий) и базового класса Base для моделей.

 models/ (Модели БД)
Определяют структуру таблиц в PostgreSQL с помощью SQLAlchemy.

counterparty.py — Модель контрагента (наименование, ИНН, контакты).

contract.py — Модель договора (привязка к контрагенту, номер, дата, сумма).

invoice.py — Модель счета/начисления (привязка к договору, сумма, срок оплаты).

payment.py — Модель платежа (привязка к счету, сумма, дата оплаты).

risk_score.py — Модель для хранения результатов скоринга (оценка риска контрагента).

 schemas/ (Pydantic-схемы)
Используются для валидации данных, которые приходят и уходят через REST API. Отделяют модели БД от контрактов API.

counterparty.py, contract.py, invoice.py, payment.py — схемы для создания, обновления и чтения сущностей.

 services/ (Бизнес-логика)
Самая важная часть сервера. Здесь нет кода API или БД, только математика и бизнес-правила.

debt_service.py — Логика расчета задолженности (сумма счета минус сумма платежей).

aging_service.py — Алгоритм Aging Analysis (распределение долга по временным интервалам: 1–30, 31–60, 61–90 и т.д.).

kpi_service.py — Расчет ключевых показателей (Total Debt, Overdue Debt, DSO, доля просрочки).

scoring_service.py — Алгоритм скоринга контрагентов (расчет риск-балла на основе истории платежей и просрочек).

 api/routes/ (REST API)
Маршруты (эндпоинты) FastAPI. Каждый файл отвечает за свой ресурс.

counterparties.py — CRUD-операции для контрагентов (GET /counterparties, POST /counterparties и т.д.).

contracts.py — Операции с договорами.

invoices.py — Операции со счетами.

payments.py — Операции с платежами.

analytics.py — Эндпоинты для получения готовых аналитических данных (Dashboard, KPI, Aging, Top Debtors).

 backend/tests/ (Тесты)
test_debt.py — Юнит-тесты для проверки корректности расчета задолженности.

test_aging.py — Тесты для проверки распределения по интервалам Aging.

test_api.py — Интеграционные тесты для проверки ответов REST API.

 desktop/ (Клиентская часть)
Каталог содержит код десктопного приложения на PyQt6.

main.py — Точка входа. Создает QApplication, инициализирует главное окно и запускает цикл событий Qt.

 views/ (Экраны приложения)
main_window.py — Главное окно (QMainWindow). Содержит боковую панель навигации и центральную область (QStackedWidget), где переключаются экраны.

dashboard.py — Главный экран с KPI-карточками, графиком динамики и списком должников.

counterparties.py — Экран со списком контрагентов (таблица, поиск, фильтры, кнопка добавления).

contracts.py — Экран управления договорами.

invoices.py — Экран управления счетами.

payments.py — Экран управления платежами.

reports.py — Экран для формирования и экспорта Excel-отчетов.

 widgets/ (Переиспользуемые компоненты)
kpi_card.py — Виджет-карточка для отображения одного показателя (например, «Просрочка: 1 730 000 ₽»).

charts.py — Виджеты для отрисовки графиков (Aging, динамика, Top-10).

 services/ (Клиентские сервисы)
api_client.py — Модуль для отправки HTTP-запросов от десктопного приложения к FastAPI. Изолирует логику сети от интерфейса.

 resources/ (Ресурсы)
styles.qss — Файл стилей (аналог CSS для Qt). Определяет цвета, шрифты, отступы и внешний вид кнопок и таблиц.

 data/seed/ (Тестовые данные)
generate_data.py — Скрипт для автоматической генерации тестового набора данных (контрагенты, договоры, счета, платежи с разными сценариями оплаты и просрочки) для наполнения базы.

 docs/ (Документация ВКР)
Материалы, связанные с дипломной работой.

architecture/ — Схемы архитектуры системы (исходники draw.io).

database/ — ER-диаграммы базы данных (исходники draw.io).

algorithms/ — Описание алгоритмов (Aging, DSO, скоринг).

ui/ — Макеты и скриншоты интерфейса пользователя.

 reports/ (Сгенерированные отчеты)
Каталог для хранения Excel-файлов, автоматически создаваемых системой (отчет по задолженности, Aging-отчет, риск-отчет). Сами файлы игнорируются Git, так как являются результатом работы программы.
